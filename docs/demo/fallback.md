# 데모 대비책 (fallback)

데모 전 점검, 라이브가 늦거나 실패할 때의 전환 대사, 전체 장애 때 녹화본으로 넘어가는 절차입니다. 장면별 대본은 [demo-script](demo-script.md), 리허설 기록은 [rehearsal](rehearsal.md)에 있습니다.

> **합성 데이터 기준.** 이 문서의 수치는 합성 데이터 기준이며 모두 기존 실측 산출물에서 인용하고 출처 경로를 옆에 적었습니다. P9 배포(셀러 데이터·상품 한도 1,000만 원·재생 정지/재개) 뒤 사전 건을 고객 페이지 `/apply`로 다시 만들었습니다(2026-11-04). P8 때의 ID(A `app-20261104-5eb963`, B `app-20261104-f58e82`, C `8c77903da5c64deba47e26d8447c90ab`, 모두 이전 신청인 `demo-healthy-001`)는 더 쓰지 않습니다. 2026-11-03 리허설 때의 ID는 [rehearsal](rehearsal.md)에 기록으로 남아 있습니다.

## 시작 전 점검

시작 5~10분 전에 순서대로 확인합니다. 명령은 [operate](../runbook/operate.md)·[deploy](../runbook/deploy.md)의 형태 그대로입니다.

- [ ] `python -m ops resume` 완료. Service Bus를 지워 둔 상태였다면 복구에 몇 분 걸립니다(실측 4.5~4.7분, `docs/runbook/operate.md`). 이미 있으면 그대로 둡니다.
- [ ] `python -m ops smoke` 통과. VNet 안 점검 항목과 콘솔 로그인 관문을 함께 확인합니다([operate](../runbook/operate.md#smoke)).
- [ ] 콘솔 접속. 주소는 `azd env get-value APPGW_FQDN`의 `https://` 주소(또는 `CONSOLE_URL`)입니다. 자체 서명 인증서라 브라우저 경고가 뜨면 넘기고 진행합니다. 접속이 403이면 WAF가 막은 것입니다. 운영자 공인 IP가 `CONSOLE_IP`와 달라진 것이니(`python -m ops window status`로 확인) `python -m ops window open --ip <현재 IP>`로 `CONSOLE_IP`를 갱신합니다 — [deploy](../runbook/deploy.md#운영자-ip가-바뀔-때)의 절차를 따릅니다. 회사 NAT처럼 출구 IP가 여러 개로 돌면 403이 반복될 수 있으니, 같은 문서의 WAF 규칙 조건 추가로 `/32` IP를 하나씩 더합니다.
- [ ] 라이브 신청 ID를 메모할 곳(종이·메모장)을 준비합니다.
- [ ] `python -m ops fault status`가 `source: off`, `policy: off`로 둘 다 꺼져 있음. 켜져 있으면 `python -m ops fault source off` / `python -m ops fault policy off`로 끕니다(`source`가 `flaky`이면 사후 재생이 실패합니다).
- [ ] 사전 건 A·B·C의 확인 방법(위 표)을 한 번씩 통과.
- [ ] 브라우저 탭 순서 맞추기: 1 고객 신청 페이지(`/apply`), 2 콘솔 목록(`/`), 3 사전 건 A, 4 사전 대출 B, 5 사전 동의 C 증명.
- [ ] 사전 대출 B의 마지막 추심 건 `추심 제안`이 아직 `심사역 승인 대기`인지 확인(리허설에서 결정했다면 다시 만듦). 선택 장면을 할 거면 대출 D가 아직 `고객 응답 대기`인지도 확인.
- [ ] 발표 시각이 21시~08시(KST)면 1:20 장면의 추심 발송이 `보류`(연락 시간 밖)로 끝난다는 것을 알고 대사를 준비(아래 표).
- [ ] 녹화본 파일을 발표 PC에서 바로 재생할 수 있는지 확인.

- 라이브 건의 동의를 만료시킨 뒤에는 그 건의 사후 재생을 시작할 수 없으므로 사전 대출 B에서는 절대 `지금 만료(데모)`를 누르지 않습니다.
- 사전 건 A·C를 쓴 뒤에도 라이브 건은 계속 진행되므로, 시간이 남으면 마지막에 목록으로 돌아가 상태를 보여 줍니다.
- 차주 화면(`/borrower`)의 `동의 철회`를 쓰지 않습니다(신청이 `철회 종료`로 끝납니다). 1:45 장면은 `지금 만료(데모)`입니다.
- 목록의 다른 `심사역 대기` 건(사전 건 C의 신청 등)을 승인하지 않습니다. 승인은 메모한 라이브 신청 ID에만 합니다.

## 전체 장애 시

콘솔 접속 불가, 큐·함수 전체 장애, 네트워크 장애로 사전 건도 열 수 없을 때입니다.

- **녹화본:** 리허설 때 발표자가 직접 대본대로 화면을 녹화합니다. 녹화본은 저장소에 넣지 않고 발표 PC에 보관합니다. 개인정보가 없는 합성 데이터 화면만 담습니다.
- **판단 기준:** 시작 전 점검이 통과하지 않거나, 0:15 장면에서 콘솔이 열리지 않으면 바로 녹화본으로 넘어갑니다. 도중에 장애가 나면 현재 장면을 끝내지 않고 넘어갑니다.
- **전환 대사:** "지금 환경에 일시적인 문제가 있어, 같은 순서로 미리 녹화한 화면으로 보겠습니다. 화면은 오늘 데모와 같은 콘솔입니다."
- **절차:** 1) 녹화본을 전체 화면으로 재생하고, 2) 재생 시점에 맞춰 [demo-script](demo-script.md)의 "말"을 그대로 읽고, 3) 데모가 끝나면 원인을 짧게 말한 뒤 질문으로 넘어갑니다. 장애 원인 확인은 데모 뒤에 [troubleshooting](../runbook/troubleshooting.md)으로 합니다.

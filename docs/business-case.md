# 비즈니스 케이스

원문 과제(Case Study 18)의 사업 목표를 이 데모가 측정한 값과 나란히 놓고, **무엇을 보였고 무엇을 아직 보이지 못했는지** 구분한다. 계산에 쓴 가정은 모두 밝힌다.

> **목표 달성 주장이 아니다.** 데모는 Mock API(마이데이터·홈택스·PG 대역)와 합성 셀러 데이터로 동작한다. 아래 측정값은 시스템의 자동화 구간이 목표를 막지 않는다는 근거일 뿐이고, 비용 60% 절감·48시간 처리·신용비용 100bp 절감을 달성했다는 뜻이 아니다. 실제 효과는 운영 전환 뒤 파일럿에서 잰다(아래 [파일럿에서 잴 것](#파일럿에서-잴-것)).

## 문제와 이해관계자

- **문제:** 고객은 재무제표는 없지만 은행 거래·세금 신고·결제 플랫폼 흐름 같은 디지털 기록이 풍부한 소기업이다. 심사는 여전히 대형 차주용 수작업 재무제표 분석이라 소액 대출은 취급 비용 대비 수익이 나지 않고, 처리에 2주가 걸리며, 부실 경보는 채무불이행 시점에야 온다.
- **경영진 후원자:** 최고사업책임자(CBO, 대출자산 성장·수익성)와 최고리스크책임자(CRO, 신용비용·통제)가 공동 추진한다. 이 설계가 에이전트에게 결정권을 주지 않고 결정론 정책 엔진과 심사역이 결정하게 한 것은 CRO의 통제 요구를 먼저 충족하기 위해서다([ADR-003](adr/ADR-003-deterministic-policy.md)).
- **제약:** 동의 범위·목적·보존 기간 안에서만 데이터를 쓴다. 자동화된 결정에 설명과 이의 경로가 있어야 한다. 국내 처리 요구가 있다(모델 처리 위치는 [ADR-002](adr/ADR-002-model-deployment.md)의 잔여 위험).

## 목표와 데모 증거

| 원문 목표 | 데모가 재는 것 | 측정값(합성 데이터) | 판단 |
|---|---|---|---|
| 소액 대출 취급 비용 60% 절감 | 신청 1건의 AI 비용 + 인프라 고정비 분담 | 월 1,000건 기준 약 $0.88/건(아래 계산) | 기술 비용은 작다는 근거. **심사역 검토 인건비·운영 비용은 재지 않아** 60% 절감 여부는 미검증 |
| 처리 시간 2주 → 48시간 | 접수 → 심사역 대기열 도착 | p95 1.2분(n=24), 게이트웨이 경로 p95 1.8분(n=48) | 자동화 구간은 48시간 예산의 0.1% 미만. **심사역 검토·자료 보완·실제 기관 API 지연은 빠져** 처리 시간 목표는 미검증 |
| 채무불이행 60~90일 전 조기 경보 | 첫 경보 → 합성 연체일 | 평균 리드 70.5~71.7일(양성 경로 2~3건), 재생 실측 66~67일 | 범위 안이지만 **연체가 나도록 설계한 합성 시나리오**다. 실제 부도 이력으로 백테스트하지 않았다 |
| 신용비용 100bp 이상 절감 | 직접 측정 불가 | 조기경보 precision·recall 1.000(탐지기 단독 precision 0.500) | 간접 근거만. 경보 뒤 재조정·회수 성과는 재지 않았다 |
| 대출자산 3억~5억 달러 확대 | 측정 범위 밖 | — | 사업 계획 수치. 데모로 검증할 수 없다 |

## 단위 경제(건당 USD 6,000 대출)

원문은 "건당 6,000달러 대출에서도 수익성을 확보하는 대출기관"을 겨냥한다. 아래는 원문 수치와 명시한 가정만으로 한 산술이다.

| 항목 | 값 | 근거 |
|---|---|---|
| 수작업 취급 원가(가정) | $3,500/건 — 대출액의 58% | Mills & McCarthy(HBS Working Paper 15-004)의 소상공인 대출 처리 원가 $3,000~4,000 중간값, `src/opsmetrics/cost.py`의 `MANUAL_USD` |
| 60% 절감 시 목표 원가 | $1,400/건 이하 | $3,500 × 0.4 |
| 데모 기술 비용(월 1,000건) | 약 $0.88/건 | 건당 AI $0.0939(게이트웨이 경로) + 월 고정비 약 $788 ÷ 1,000. 고정비 = 측정 $304.73 + 측정 뒤 추가된 APIM 약 $51·Functions always ready 약 $62·App Gateway WAF v2 약 $370. 측정 시점이 다른 값을 더한 계산값 |
| 남는 예산 | 약 $1,399/건 | 심사역 검토·운영·조달 비용이 이 안에 들어와야 한다. **이 부분이 비용 목표의 실제 승부처이고 데모는 재지 않았다** |
| 신용비용 100bp의 가치 | 대출 1건 연 $60, 자산 3억~5억 달러면 연 $3M~5M | $6,000 × 1%, $300M~500M × 1% |

- 기술 비용은 물량에 민감하다: 같은 계산으로 월 100건이면 약 $8.0/건, 10,000건이면 약 $0.17/건이다. 대부분 고정비(App Gateway·Service Bus Premium 등)라 물량이 늘면 빠르게 준다([비용 모델](cost-model.md)).
- 2026-11-07 분석가를 `gpt-5.6-sol`로 바꾼 뒤 재측정한 건당 AI 비용은 $0.0738(n=10)로, 위 계산의 $0.0939보다 낮다. 위 계산은 보수적으로 $0.0939를 그대로 쓴다([비용 모델](cost-model.md#게이트웨이-경로-건당-ai-비용)).
- 수작업 원가는 미국 문헌값이다. 실제 원가는 대출기관의 활동기준원가(ABC)로 바꿔 넣어야 한다.

## 미추진 시 비용

- **시장:** 원문은 핀테크가 이미 거래 흐름으로 심사하고 오픈뱅킹 적용 범위가 매달 넓어진다고 본다. 수작업 심사를 유지하면 원문의 3억~5억 달러 자산 확대 기회를 잃는다.
- **신용비용:** 경보가 부도 시점에 오는 구조를 그대로 두면, 위 산술로 자산 3억~5억 달러 기준 연 $3M~5M(100bp)의 절감 기회를 놓친다.
- **원가 구조:** 수작업 원가 가정($3,500)이면 $6,000 대출은 취급만으로 대출액의 절반 넘게 쓴다. 이 구조로는 해당 고객군에 들어갈 수 없다.
- 이 세 항목은 원문의 사업 가정에서 나온 값이다. 데모 측정값이 아니다.

## 파일럿에서 잴 것

원문의 성과 지표 다섯 개(취급 건당 비용, 처리 시간, 경보 선행 기간, 신용비용, 대출자산 성장)를 운영 전환 뒤 이렇게 잰다.

| 성과 지표 | 데모에 이미 있는 계측 | 파일럿에서 더할 것 |
|---|---|---|
| 취급 건당 비용 | 건당 AI 토큰 비용·고정비(`ops report`, [비용 모델](cost-model.md)) | 심사역 검토 시간(콘솔 열람 → 결정), 대출기관 ABC 원가 |
| 처리 시간 | 접수 → 심사역 대기 p50/p95(SLO1), 결정 반영 시간 | 실제 기관 API 지연, 자료 보완 왕복, 심사역 결정까지 전체 시간 |
| 경보 선행 기간 | 첫 경보 → 연체일(평가 하네스 4장) | 실제 연체 이력 백테스트, 섀도 모드 운영(경보만 내고 조치 안 함) |
| 신용비용 | 없음 | 경보 군과 대조군의 12개월 손실률 비교 |
| 대출자산 성장 | 없음 | 승인 건수·금액, 기존 심사 대비 승인율 |

### 오프라인 기준선: 신청당 원가와 실행당 원가

저장소 루트 PowerShell에서 프로젝트 Python 환경으로 실행한다. 기간 안에 종결된 **모든** 신청을 한 줄씩 담은 로컬 UTF-8 CSV를 준비한다. `application_id`는 가명 키이며 이름·고객번호·거래 원문은 넣지 않는다. 예시는 기관 측정값이 아닌 가정이다.

```csv
application_id,outcome,hands_on_minutes,labor_krw_per_hour,nonlabor_krw
a,funded,30,20000,1000
b,withdrawn,15,20000,0
```

```powershell
python -m src.opsmetrics.pilot cases.csv --basis hypothetical --fixed-krw 1500
```

`outcome`은 `funded`, `declined`, `rejected`, `withdrawn`, `other_unfunded` 중 하나다. 실작업 분은 자료 확인·검토·보완 등 **실제로 작업한** 사람별 시간을 더하고 대기 시간은 뺀다. 복수 심사역이면 시간 가중 시급을 쓴다. 총원가는 각 건의 `분 × 현지 시급 / 60`과 건별 비인건비, 기간 배부 고정비(한 번만)를 합한 값이다. 거절·철회 원가도 두 분자에 들어간다. 예시는 45분·17,500원으로 **전체 신청당** 22.5분·8,750원(2건), **실행당** 45분·17,500원(1건)이다. 실행 0건이면 실행당 값은 `null`이다. 중복 키·필수값 누락은 오류이며 0으로 채우지 않는다. 모든 입력이 기관 실측일 때만 `--basis observed`로 표시한다.

### 마켓 자료만 바꾸는 합성 짝비교

```powershell
$env:PYTHONPATH = 'src'
python -m opsmetrics.paired_pilot
```

`build_demo_cases`의 시드 고정 셀러 21곳을 메모리에서 재생한다. A는 계좌 프로필·거래, B는 **같은 A에 마켓 판매 성과만** 더한다. 계좌에 찍힌 정산 입금·세금 출금은 양쪽에 남고, 별도 PG 정산 원장과 세금 신고서는 양쪽에서 뺀다. 기준일(2026-11-01), 요청액(330만 원)·기간(6개월), 규칙 기반 거래 분류, 정책 `2026.11-v4`는 같다. 마켓 자료가 없으면 그 규칙은 적용되지 않는다. 신규 신청·실행·고객 연락·Azure·LLM 호출은 없다.

JSON `pairs`는 가명 셀러별 두 정책 판정·한도·사유와 `limit_delta_krw`(B−A)를 담는다. 분모는 **서로 다른 셀러 21쌍**이지 판정 42개나 실행 건수가 아니다. B의 마켓 원천이 실제로 있는 쌍은 `marketplace_observed_pairs`(이번에는 21/21)로 따로 센다.

| A → B 정책 판정 | 쌍 | 쌍별 한도 변화 |
|---|---:|---:|
| 부적격 → 회부 (knitroom-04, leather-14, tint-17) | 3 | 각 +330만 원 |
| 적격 → 부적격 (petfood-07) | 1 | −330만 원 |
| 적격 → 회부 (ceramic-08) | 1 | 0원 |
| 판정 불변 | 16 | 각 0원 |

판정은 5/21쌍, 한도는 4/21쌍에서 바뀌었다(한도 차이 합 +660만 원). 이는 **정책 반응**이지 승인 실적·증분 자산·손실 절감이 아니다. 심사역 번복(`human_override`)과 실작업 시간(`hands_on_minutes`)은 별도 필드이며 두 군 모두 미관측(`null`)이다. 미관측은 무번복이나 0분이 아니다.

**사람 평가와 변경 기준.** 후속 비개입 평가에서는 같은 시점까지의 가명 증거 묶음을 쓰고 건마다 서로 다른 심사역에게 A/B를 무작위 배정한다. 심사역별 두 군의 배정을 균형화하고 상대군 판정과 이후 상환 결과는 가린다. 정책 제안과 심사역의 모의 최종 판단·한도, 번복 여부·사유, 대기 제외 실작업 분을 각각 기록한다. 번복률은 판단이 기록된 건만, 시간 차이는 양쪽 시간이 있는 쌍만 분모로 삼고 완전쌍·누락 수도 낸다. 고객 결정에는 반영하지 않는다.

운영 모델을 바꾸기 전에 리스크·업무 책임자가 표본 규모, 허용 위험과 최소 시간·원가 개선폭을 정한다. 대표성 있는 별도 이력에서 상환·손실 및 집단별 위험을 확인하고, 후보와 현행의 동일 건 사람 평가로 근거 오류·번복·시간·현지 총원가를 비교한다. **위험이 허용 범위 안이고 시간·원가 개선이 기준을 충족한다는 증거가 모이기 전에는 현행 운영 모델을 유지한다.** 이 합성 비교는 모델 자체를 비교하지 않았다.

### 콘솔 4개 업체 회귀: 판정뿐 아니라 근거도 비교

`python -m opsmetrics.paired_pilot --console-cohort`은 위 21쌍과 **다른 실험**이다. 기준일 2026-11-20, 신청 500만 원·6개월, 계좌·세무·PG를 고정하고 마켓 성과만 추가한다. 대전밀빵공방은 적격 500만 원 그대로, 판교손뜨개공방은 부적격에서 **추가 심사** 500만 원으로, 광교펫푸드랩은 판매정지 때문에 적격에서 부적격으로 바뀐다. 이천도예공방은 추가 심사·500만 원 그대로지만 채널 편중 외에 반품률 사유가 생긴다. 마켓 자료 미제공은 0점이 아니며, 부분 제공 지표는 관측된 플랫폼에만 해당한다.

### AI 의견서 비개입 실험: 사람의 시간과 원가

**실측 결과(2026-11-20):** 측정 도구와 비교 절차를 구현하고 합성 데이터로 계산을 검증했다. 실제 심사역이 같은 자료를 의견서 제공·미제공 조건에서 각각 검토한 기록은 **0쌍**이다. 따라서 건당 심사 시간 차이와 변동원가 차이는 모두 **미측정**이다. 아래의 30분과 18분은 계산 예시이며, 실제로 12분을 절감했다는 뜻이 아니다.

한 신청의 자료·정책 버전·정책 판정·한도를 동결해 같은 `evidence_version`으로 두 심사역에게 배정한다. 한 명에게만 AI 의견서를 제공한다. 두 심사역은 상대 판단과 실제 상환 결과를 보지 않으며 모의 판단을 고객에게 반영하지 않는다. 사례마다 군을 무작위 배정하고 심사역별 두 군 참여 수를 균형화한다. 실명·상호·고객 ID·원문 대신 연구용 토큰과 사유 코드만 로컬 UTF-8 CSV에 기록한다.

```csv
case_id,evidence_version,policy_result,reviewer,arm,hands_on_minutes,labor_krw_per_hour,nonlabor_krw,requests,errors,decision,override_reason
a,v1,refer,r1,no_memo,30,20000,0,2,1,refer,
a,v1,refer,r2,memo,18,20000,150,1,0,eligible,verified_evidence
```

`python -m src.opsmetrics.officer_pilot reviews.csv --basis hypothetical`로 집계한다. 예시는 **합성 검산**으로 두 군의 건당 실작업 시간은 30분과 18분, 건당 변동원가는 10,000원과 6,150원이다. 의견서 생성비는 해당 건의 비인건비에 포함하고 대기 시간과 기간 고정비는 제외한다. `requests`는 추가 자료 요청 횟수, `errors`는 독립 검토자가 동일한 기준으로 확인한 근거 오류 수다. 두 판정 필드는 `eligible`, `refer`, `ineligible` 중 하나다. 정책과 모의 판단이 다를 때만 `verified_evidence`, `missing_evidence`, `policy_exception`, `other` 중 하나를 남긴다.

분모는 제출된 사례 중 **서로 다른 심사역의 완전쌍**이다. 한쪽만 제출하면 누락 사례로 별도 집계하고, 어느 쪽도 제출하지 않은 사례는 배정 명부에서 별도로 대조한다. 결과 차이는 `memo − no_memo`이며 음수면 의견서 군의 시간 또는 원가가 낮다. 모든 값이 기관 실측인 경우에만 `--basis observed`를 쓴다.

`reviewer_assignment`가 `confounded`이면 심사역이 한 군에만 참여해 시간 차이가 의견서 때문인지 심사역 때문인지 구분할 수 없다. `imbalanced`는 일부 교차 참여가 있지만 두 군의 배정 수가 다르다는 뜻이다. 완전쌍이 없으면 시간·원가·품질 측정값은 모두 `null`이다. 균형 배정이더라도 무작위 배정이나 기관 실측의 진위를 CLI가 검증하는 것은 아니다.

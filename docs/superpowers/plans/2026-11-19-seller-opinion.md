# 마켓 판매 성과 심사 의견 구현 계획

> 실행: executing-plans 또는 subagent-driven-development. 아래 체크박스로 추적한다.

**목표:** 지표 나열을 근거·해석·한계·다음 확인 사항으로 이어지는 의견으로 바꾼다.

**구조:** 기존 분석가와 검토자의 반성 루프를 사용한다. 분석가가 실제 근거 ID를 주장에 붙이고, 검토자가 요약 자체의 적합성을 독립 판정한다.

**기술:** Python, Pydantic, Foundry 프롬프트 에이전트, pytest.

**설계:** `docs/superpowers/specs/2026-11-19-seller-opinion-design.md`

## 공통 제약

정책·모델·최종 결정 권한·저장된 과거 의견서는 변경하지 않는다. 숫자 검증, 개인정보 마스킹, 기존 최대 라운드 수를 유지한다.

## 검토 초점

신호 일치, 신호 충돌, 마켓 자료 부재, 평점의 표본 부족, 정산 예정금과 실입금 혼동. 단순 열거와 근거 없는 인과 추론도 검토자가 반려한다.

## 분석·검토 경로 수정

- [ ] `tests/agents/test_underwriting.py`에서 셀러 근거가 있는 입력과 없는 입력을 구분하고, 주장이 통과해도 요약이 반려되면 다음 라운드로 이어지는 테스트를 먼저 실패시킨다.
- [ ] `src/agents/underwriting.py`의 분석 지침을 갱신한다. `_reviewer_input`에 사용 가능한 마켓 근거를 넘기고 `ReviewerOutput`과 JSON 스키마에 요약 판정을 추가해 `_review_issues`에서 반영한다.
- [ ] 기존 모의 검토 응답들을 새 계약과 일치시키고, 관련 테스트 및 전체 로컬 테스트를 실행한다. 실제 모델 품질은 유료 평가 없이 단정하지 않는다.

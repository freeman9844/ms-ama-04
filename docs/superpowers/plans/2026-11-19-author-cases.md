# 이정운 저자 사례 9편 편집 계획

> 실행 방식: `executing-plans`로 이 세션에서 직접 작성한다.

**목표:** 금융권 설계자가 결정 권한, 중단 조건, 복원 범위를 검토할 수 있도록 기존 백서에 근거 있는 저자 사례를 넣는다.

**구성:** `docs/thought-leadership.md`의 일곱 원칙과 체크리스트를 유지한다. 서론에서 제기한 질문에 결론에서 답한다.

**형식:** 한국어 Markdown. [승인된 설계](../specs/2026-11-19-author-cases-design.md)를 따른다.

## 공통 제약과 검토 초점

저자는 이정운. 저자의 요청과 팀의 실행을 혼동하지 않는다. 직책이나 고객 발언을 창작하지 않는다. 과거 측정과 현재 구성, 합성 평가와 실제 고객 성과, 재배포와 데이터 복구, 추정 비용과 청구액을 구분한다.

## 작업 1: 백서 편집

- [ ] 원문과 인용 자료를 읽고 저자 사례 자리 아홉 곳과 미완성 편집 문구를 확인한다.
- [ ] 서론에는 심사역을 위한 의견을 요청한 배경을, 원칙 1~7에는 각각 요약 독립 반려, 미납 이벤트 재전달, 숫자 검증과 해석 검토의 차이, 데이터 수집 보고 불일치, 모델 선택과 건당 비용, 배포와 동작 확인의 차이, 합성 평가의 한계를 쓴다. 결론은 다음 설계 검토에서 사용할 질문으로 마무리한다.
- [ ] 저자·최종 수정일·현재 구성·출처를 갱신한다. 근거는 배포 이력과 개별 평가·부하 보고서에 연결한다. 발행했다고 표시하지 않는다.
- [ ] 저자 사례 9개, 작성 지시문 0개, 인용 링크의 실제 대상, 수치의 분모와 시점, 저자 표기를 확인한다. 문서 변경만 로컬 커밋하고 GitHub에는 별도 요청 없이 푸시하지 않는다.

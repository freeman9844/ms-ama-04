# 상환 충당·비개입 파일럿 구현 계획

**목표:** 상환 잔액과 추심 근거를 일치시키고 실측 가능한 사업 검증 도구를 제공한다.
**구조:** 거래 충당을 순수 Python 로직으로 유지하고 기존 재생·추심·콘솔에 연결한다. 파일럿은 운영 쓰기 권한 없는 오프라인 집계로 분리한다.
**기술:** Python, pytest, Jinja, 기존 정책 엔진.
**설계:** [상환 충당과 비개입 파일럿](../specs/2026-11-20-repayment-pilot-design.md).

## 공통 제약과 검토 초점

과거 완납 기록 보존, 거래 재처리 멱등성, 같은 날 여러 회차, 이전 주의 추심 제안, 실행 건수 0인 표본을 확인한다. 모델 호출과 Azure 배포는 하지 않는다.

### 1. 원장·추심·화면
- [ ] `tests/agents/test_repayment.py`에 50만 원 중 1원, 복수 거래, 익주 지연 납부, 중복 및 초과분 사례를 추가해 기존 판정 실패를 확인한다.
- [ ] `src/agents/repayment.py`와 `src/orchestrator/journey/monitoring.py`에서 회차별 배분·잔액을 저장하고 복수 추심 건, 재처리, 완납 뒤 대기 제안 무효화를 검증한다.
- [ ] `src/console/templates/loan.html`과 상태 번역에 부분납·잔액을 표시하고, `detail.html`과 영문 카탈로그에서 정산 문구를 수정한다.
- [ ] 에이전트·오케스트레이터·콘솔 관련 pytest를 실행한다.

### 2. 심사 업무 기준선
- [ ] `src/opsmetrics/pilot.py`에 가명 신청별 실작업 시간과 현지 원가 입력을 집계하는 오프라인 인터페이스를 추가한다. 총원가를 전체 신청 건수와 실행 건수로 각각 나눈다.
- [ ] `tests/opsmetrics/test_pilot.py`에서 거절·철회 소요 비용 포함, 실행 0건에서 나눗셈 불가, 중복·누락값의 명시적 처리를 검사한다.

### 3. 짝지은 비교와 모델 판단
- [ ] 같은 합성 신청과 같은 정책 버전으로 마켓 자료만 제외/포함해 두 결과를 생성한다. 새로운 신청·고객 연락·대출 결정을 생성하지 않는다.
- [ ] 짝별 정책 판정·한도 차이, 심사역 번복·검토 시간의 측정 여부를 구분한다. 자료 미제공을 0점으로 대체하지 않는다.
- [ ] `docs/business-case.md`에 사용법·분모·사람 평가 기준을 기록하고, 합성 자료로 로컬 검증한다. 위험·시간·비용의 비교 자료가 없으면 운영 모델 유지로 결론낸다.

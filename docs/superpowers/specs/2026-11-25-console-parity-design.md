# 영어·USD 심사 콘솔 기능 복원

## 목표와 선택

심사역은 USD 신청 하나를 열어 신청 경과, 정책 계산, 현금흐름, AI 의견 검토와 최종 결정을 한 화면에서 추적할 수 있어야 한다. 비교 기준은 USD 병합 직전 `3ba299b`의 기능이며, 실제 금액·판정의 기준은 각 신청에 저장된 상품과 기록이다. 기본 언어는 영어, 사용자가 선택한 한국어도 같은 화면을 사용한다.

- **선택: 기존 상세 화면을 공통화한다.** 탭 탐색과 패널을 공유하고, 상품별로 값·단위·정책 설명을 제공한다. 같은 화면 개선을 두 번 하지 않는다.
- USD 전용 화면에 일부 카드만 복사하면 빨리 시연할 수 있으나 나머지 누락과 이중 유지보수가 계속된다. 구버전 전체 롤백은 신규 USD 신청과 이미 생성된 대출을 처리하는 계약이 달라 제외한다.

## 복원할 화면과 근거

`app.py`의 `detail()`이 `usd_detail.html`로 우회하지 않도록 한다. `detail.html`의 탭 구조·키보드 탐색·오류 시 결정 탭 복귀를 공유하고, `detail_view`가 적용한 권한·마스킹의 경계를 유지한다. `dashboard.py`, `assessment.py`, `opinion.py`에서 공통 화면이 요구하는 값을 준비한다. 템플릿에 가짜 KRW 필드를 만들어 넣지 않는다.

| 화면 | 복원 및 판정 기준 |
|---|---|
| 타임라인·요약 | 저장된 단계·시간·오류·SLA, 정책/AI/심사역 상태를 분리한다. 승인 권고만 있는 신청은 승인 완료로 표시하지 않는다. |
| 현금흐름·마켓 | 월별 매출과 지출, 순현금흐름, 상환 여력, 정산 대사, 신호등, 플랫폼과 제재 내역을 원래 탭에서 찾을 수 있다. 집계·거래는 동의 범위와 기존 근거만 쓴다. 정산 예정액은 확정 입금이 아니다. |
| 정책 | 버전별 판정·한도·관측값·기준값을 표시한다. 한도 후보 및 산식을 설명할 때 기존 정책 설명 로직을 재사용하고, 버전 또는 저장 결과와 맞지 않으면 산출 근거를 표시할 수 없다고 쓴다. KRW 단위 절사 규칙을 USD에 쓰지 않는다. |
| AI 의견·근거 거래 | 독립 검토를 통과한 현행 의견, 확인 사항, 근거·거래·반사실을 구분한다. 마지막 심사 시도의 라운드 번호, 결과, 근거 검사·검토 지적 건수는 기록된 범위만 표시한다. 의견 발행 실패 시에도 안전한 실행 이력은 볼 수 있지만 반려 초안·검토자 자유 서술은 노출하지 않는다. |
| 동의·데이터, 심사역 결정 | 동의 상태, 삭제 후 빈 상태, 권한별 표시 및 기존 결정 폼·도우미를 유지한다. 감사자는 결정할 수 없다. 결정 API, 정책, 심사·추심 흐름은 변경하지 않는다. |

금액은 저장된 정수 센트로 계산한 뒤 표시 단계에서만 `$5000` 형태로 반올림한다. 편집 가능한 승인 금액의 센트는 보존한다. 비율·건수·기간에는 금액 포매터를 쓰지 않는다. 누락과 실제 0을 구분한다. USD 화면에 한국어를 선택해도 거래 통화와 영문 원본은 바뀌지 않는다. 기존 KRW 동작은 로컬 합성 자료로 검증하며, 삭제한 데이터를 복구하지 않는다.

## 상세 이외 화면의 차이

구현 시 `3ba299b` 대비 고객 메뉴 6개, 신청 대시보드, 대출·사후 모니터링, 이의·운영 지표를 **카드·도표·링크·행동·빈 상태** 단위로 대조한다. 동일 기능은 보존하고, 단순 표시 누락은 동일한 저장 근거가 있을 때만 복구한다. 다른 상품 정의나 미수집 데이터 때문이면 차이와 이유를 명시하고 재계산·백필하지 않는다. 쓰기 경로나 금융 모델 변경이 필요한 차이는 별도 승인 대상으로 분리한다.

예를 들어 4주 달성률은 KRW 전망에서 실제로 사용하는 계수다. USD 전망에 같은 계수가 없다면 해당 값을 `0%`로 채우거나 KRW 방식으로 전망했다는 설명을 붙이지 않는다. 실제·기대 입금이나 전망 그래프는 USD 원장과 대조한다.

## 완료 및 운영 경계

1. 먼저 미커밋 USD 운영 수정과 새 회귀 테스트의 정확한 기준 버전을 로컬에서 보존한다. 관련 없는 루트 작업, 운영 플래그, WAF 및 데이터에는 손대지 않는다.
2. 같은 로컬 테스트가 한·영과 USD·KRW 상세 양쪽에서 타임라인과 8개 탭 **내용**을 검사한다. 부분 자료, 미검토·실패, 권한, 0과 결측, 통화 혼용, 정확한 입력 금액도 검사한다. 영어 데스크톱과 모바일에서 탭·레이블·차트를 확인한다.
3. 정상·회부·거절·사후 위험 표본으로 화면 대조 결과를 남긴다. 운영 반영은 별도 승인 후 콘솔만 배포하고 읽기 전용으로 확인한다: Pet Care는 1·2라운드 반려 뒤 3라운드 통과와 심사역 대기, Bakery는 13주 완료, Daily Look은 13주 미납과 추심 제안 보류. 승인·재신청·재생·삭제 없이 확인한다.

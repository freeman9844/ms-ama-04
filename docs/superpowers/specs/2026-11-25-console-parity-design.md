# 영어·USD 심사 콘솔 기능 복원

## 목표와 선택

심사역은 USD 신청 하나를 열어 신청 경과, 정책 계산, 현금흐름, AI 의견 검토와 최종 결정을 한 화면에서 추적할 수 있어야 한다. 비교 기준은 USD 병합 직전 `3ba299b`의 기능이며, 실제 금액·판정의 기준은 각 신청에 저장된 상품과 기록이다. 기본 언어는 영어, 사용자가 선택한 한국어도 같은 화면을 사용한다.

- **선택: 기존 상세 화면을 공통화한다.** 탭 탐색과 패널을 공유하고, 상품별로 값·단위·정책 설명을 제공한다. 같은 화면 개선을 두 번 하지 않는다.
- USD 전용 화면에 일부 카드만 복사하면 빨리 시연할 수 있으나 나머지 누락과 이중 유지보수가 계속된다. 구버전 전체 롤백은 신규 USD 신청과 이미 생성된 대출을 처리하는 계약이 달라 제외한다.

## 복원할 화면과 근거

`app.py`의 `detail()`이 `usd_detail.html`로 우회하지 않도록 한다. `detail.html`의 탭 구조·키보드 탐색·오류 시 결정 탭 복귀를 공유하고, `detail_view`가 적용한 권한·마스킹의 경계를 유지한다. `dashboard.py`, `assessment.py`, `opinion.py`에서 공통 화면이 요구하는 값을 준비한다. 템플릿에 가짜 KRW 필드를 만들어 넣지 않는다.

| 화면 | 복원 및 판정 기준 |
|---|---|
| 타임라인·요약 | 저장된 단계·시간·오류·SLA, 정책/AI/심사역 상태를 분리한다. 승인 권고만 있는 신청은 승인 완료로 표시하지 않는다. |
| 현금흐름·마켓 | 월별 매출과 지출, 순현금흐름, 상환 여력, 정산 대사, 신호등, 플랫폼과 제재 내역을 원래 탭에서 찾을 수 있다. 집계·거래는 동의 범위와 기존 근거만 쓴다. 정산 예정액은 확정 입금이 아니다. |
| 정책 | 버전별 판정·한도·관측값·기준값을 표시한다. 한도 후보 및 산식을 설명할 때 기존 정책 설명 로직을 재사용하고, 버전 또는 저장 결과와 맞지 않으면 산출 근거를 표시할 수 없다고 쓴다. KRW 단위 절사 규칙을 USD에 쓰지 않는다. |
| AI 의견·근거 거래 | 독립 검토를 통과한 현행 의견, 확인 사항, 근거·거래·반사실을 구분한다. 마지막 심사 시도의 라운드 번호, 결과, 근거 검사·검토 지적 건수는 기록된 범위만 표시한다. 의견 발행 실패 시에도 안전한 실행 이력은 볼 수 있지만 반려 초안·검토자 자유 서술은 노출하지 않는다. |
| 동의·데이터, 심사역 결정 | 동의 상태, 삭제 후 빈 상태, 권한별 표시 및 기존 결정 폼·도우미를 유지한다. 감사자는 결정할 수 없다. 결정 API, 정책, 심사·추심 흐름은 변경하지 않는다. |

금액은 저장된 정수 센트로 계산한 뒤 표시 단계에서만 `$5000` 형태로 반올림한다. 편집 가능한 승인 금액의 센트는 보존한다. 비율·건수·기간에는 금액 포매터를 쓰지 않는다. 누락과 실제 0을 구분한다. USD 화면에 한국어를 선택해도 거래 통화와 영문 원본은 바뀌지 않는다. 기존 KRW 동작은 로컬 합성 자료로 검증하며, 삭제한 데이터를 복구하지 않는다.

## 상세 이외 화면의 차이

비교 기준은 `3ba299b`의 KRW 화면, 작업 4 시작점은 `adb0aab`이다. 기본 경로는 USD, `/legacy`는 KRW다. 목록은 조회 한도 **이전에** 상품을 구분하며 상세는 저장 문서의 상품을 따른다(`adapters.py`, `app.py`). 언어 전환으로 포트폴리오·통화·권한은 바뀌지 않는다.

| 화면 | 카드·도표·빈 상태 | 링크·행동 및 판정 근거 |
|---|---|---|
| 고객 ① 대출 신청 | **상품 변경:** 사업자·동의 3종·조건 카드는 유지. 원 대신 $100–$10,000, 센트 입력, 3–6개월. | 선택 → `/apply`; 새 신청은 USD만 가능. 접수 플래그가 닫히면 안내·버튼 비활성. KRW 재접수는 쓰기 계약 변경이라 제외(`apply.html`, `customer.validate_request`). |
| ② 신청 현황 | **보존:** 최근 신청 히어로·4단계·이력, 실제 결정액/금액 미확인, 기록 없음. 권고는 결정액이 아니다. | 고객 접수 건만 진행 상세로 연결. 동의가 생기기 전에도 같은 차주의 같은 상품 신청 조회(`borrower_page`, `_progress.html`). |
| ③ 상환 플랜 | **보존:** 제안 전/후 일정·선택 결과·심사 대기. 대출 없음과 제안 없음을 구분. | 열린 제안의 이동/분할/유지만 선택. USD 이동 기준은 모니터링 전 정산액이 가장 큰 플랫폼의 지급 이력. 옵션 생성·승인 흐름은 변경하지 않음(`borrower_plans.html`, `journey.monitoring._plan_options`). |
| ④ 받은 안내 | **보존:** 날짜·문구·상태 표, 없으면 안내 없음. 별도 차트 없음. | 고객 메뉴에서 읽기만 가능. 같은 대출의 해당 재생에서 오늘까지 발송된 연락만 표시, 보류를 발송으로 세지 않음(`borrower_plan`, `borrower_notices.html`). |
| ⑤ 동의 관리 | **보존:** 목적·범위·만료·철회·삭제 안내, 동의 없음/삭제 당시 잔존 파일 없음. **추가:** 삭제 대상 인벤토리 미확인 시 완료 안내 보류. | 유효 동의만 철회, 증명이 있을 때만 링크. 상품별 복귀·기존 권한과 삭제 경계 보존, 원천 복구 없음(`borrower_consents.html`, `proof.html`). |
| ⑥ 고객 이의 | **보존:** 결정 건 선택·접수 이력·회신 원문, 과거 의견 참조 회신은 감사 기록만. 결정 전이면 제출 폼 대신 안내. | 자기 상품의 결정된 신청만 제출. USD 재심 결과는 센트 원본, 제출/회신 생성은 변경하지 않음(`borrower_grievances.html`, `borrower_grievance`). |
| 신청 대시보드 | **표현 변경:** 전체·대기/SLA·진행·승인율 4 KPI와 상태 도넛 유지. 권고 5종은 고정 SVG 대신 영어가 줄바꿈되는 레이블·건수·막대. 결정이 없으면 승인율 `-`, 신청이 없으면 빈 행. | 행 → 공통 상세, 3초 갱신, 결정권자만 새 신청. 같은 상품 전체 통계와 smoke/load/fault 제외 최근 목록 구분; USD 20건(종전과 동일), 보관함 100건(`home_summary`, `list.html`, `_rows.html`). |
| 대출 목록·사후관리 | **보존:** 대출/재생/완주/경보 KPI·빈 목록, 주차·경보 근거·상환/미납 원장·연락·추심 제안과 이력. 주차가 없으면 주간 표/전망 없음. | 목록 ↔ 대출 ↔ 신청, 주차 → 경보/미납 건. 재생·재개/종료, 계획·추심·재조정 결정은 기존 역할/대기 상태/CSRF를 따름. USD 수정 발송은 검증된 문구 선택, 자유문 편집은 백엔드 승인 범위 변경이라 제외(`loan.html`, `loan_view`, `usd_text_choices`). |
| 주간 흐름·PG | **상품 차이:** USD 실제 매출 막대와 심사 시점 주 평균 기대선(`revenue_cents`, `expected_revenue_cents`); KRW 기대선은 채널 주기·계절 지수 반영. USD 주간 버퍼 일수·고금리 건수, PG 반품·보류·공제 합계는 **미수집**. 버퍼 관측이 없으면 선·오른쪽 축 없이 `-`; USD 원장에는 주문·실지급만 표시하고 빈 필드는 `-`, 원장 자체가 없으면 별도 안내. | `observe_usd`의 `row`, `journey.monitoring`의 `pg_weeks`, `_expected_vs_actual` 대조. 기준선 버퍼를 매주 복사하거나 원천을 추가 집계하지 않음. |
| 4주 전망 | **표시 복원:** 시작/최저 잔고·날짜·일별 잔고선에 더해, 저장된 상환일의 **출금 직전 잔고와 예정 상환액** 표시(실제 납부액 아님). **다른 전망:** USD는 최근 영업일당 순현금흐름·대표자 인출·일정으로 전망. KRW 4주 달성률·입출금 항목별 28일 합계가 없으므로 표시하지 않음. | `project_usd.path`의 `date/balance_cents/before_payment_cents/installment_cents`와 같은 주의 최저·부족일 사용. 계수나 날짜 키 누락은 0%·부족 없음이 아님. 조회만 하며 전망 재산출·재생 없음. |
| 심사역 이의 | **표시 복원:** 접수 스냅숏의 원결정·버전·사유·검토된 반사실·회신은 유지. USD 금액 근거만 달러로 표시하고 재심 입력 옆에 기록된 한도 복원. 비율은 그대로. 목록 없음·감사자 읽기 전용 유지. | 목록 ↔ 이의 상세 → 신청. 유지/재심은 기존 결정 권한·검증 사용; 최초 심사 기록은 불변(`journey.grievance._snapshot`, `grievance.html`). |
| 운영 지표 | **보존:** 지연/성공률·비용·대기/SLA·권고 일치/예외 승인, 결정 퍼널·단계 시간·처리량·모델 비용·사유/플래그·공정성 표와 그래프. 일치율은 같은 상품의 신청액/승인액 비교. **표시 보정:** 공정성 격차는 비교 가능한 두 그룹이 없으면 `—`, 동률이면 `0.0%p`; 원형 통제에 쓸 부하 표본이 없는 USD 데모도 `—`. | 상품별 run 또는 최근 100건 선택(GET), 빈 범위 안내. KRW 부하 제출 안내/보고서는 USD 측정 결과가 아니다(`ops.scope_docs`, `opsmetrics.projection`, `opsmetrics.fairness`, `opsjob.azure`). 새 측정 실행·원형 라벨 수집·금융 모델 변경은 하지 않음. |

**오프라인 표본:** 2026-11-24 기준 합성 Bakery(정상 `eligible`), Knitroom(회부 `S001/R107`), Pet Food(거절 `R003`)는 로컬 원천과 USD 규정으로 대조했다. 사후위험은 합성 상환일 직전 $0·예정 $72·전망 −$72 기록으로 확인했다. 이는 운영 차주의 판정·잔고나 Pet Care의 검토 라운드를 확인한 결과가 아니다.

## 완료 및 운영 경계

1. 먼저 미커밋 USD 운영 수정과 새 회귀 테스트의 정확한 기준 버전을 로컬에서 보존한다. 관련 없는 루트 작업, 운영 플래그, WAF 및 데이터에는 손대지 않는다.
2. 같은 로컬 테스트가 한·영과 USD·KRW 상세 양쪽에서 타임라인과 8개 탭 **내용**을 검사한다. 부분 자료, 미검토·실패, 권한, 0과 결측, 통화 혼용, 정확한 입력 금액도 검사한다. 영어 데스크톱과 모바일에서 탭·레이블·차트를 확인한다.
3. 정상·회부·거절·사후 위험 표본으로 화면 대조 결과를 남긴다. 운영 반영은 별도 승인 후 콘솔만 배포하고 읽기 전용으로 확인한다: Pet Care는 1·2라운드 반려 뒤 3라운드 통과와 심사역 대기, Bakery는 13주 완료, Daily Look은 13주 미납과 추심 제안 보류. 승인·재신청·재생·삭제 없이 확인한다.

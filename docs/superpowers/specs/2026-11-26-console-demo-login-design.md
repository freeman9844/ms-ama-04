# 심사 콘솔 데모 로그인 화면 설계

## 의도
데모를 보는 사람에게 "심사역이 로그인하고 콘솔에 들어가는 장면"을 보여 준다. 보안 강화가 목적이 아니다. 접근 차단은 지금처럼 App Gateway WAF 운영자 IP 규칙이 맡는다([ADR-011](../../adr/ADR-011-appgw-waf-entry.md)).

## 목표 · 비목표 · 반목표
- 목표: 데모 모드에서 심사역 화면에 들어가기 전에 로그인 화면이 나오고, 로그아웃하면 다시 로그인 화면으로 돌아온다. 주소를 직접 열거나 뒤로 가기를 눌러도 로그인 없이 들어가지 않는다.
- 비목표: 역할별 계정(심사 관리자·감사자), 고객 로그인, 실제 사용자 식별·감사 추적. 결정 기록은 지금처럼 `demo-operator`로 남는다.
- 반목표: 로그인 때문에 데모가 막히면 실패다. 미리 채워진 값으로 한 번에 들어가야 한다. Easy Auth 모드·고객 콘솔·미리보기·기존 테스트의 동작이 바뀌면 안 된다.

## 제약
- Entra 로그인은 테넌트가 사용자 동의를 막아 쓸 수 없다([ADR-007](../../adr/ADR-007-demo-auth-mode.md)).
- 저장소에 비밀번호 같은 비밀 값을 커밋하지 않는다.
- 앞단 구조(App Gateway WAF → 내부 ACA 콘솔)는 건드리지 않는다.

## 검토한 방식
| 방식 | 장점 | 대가 | 결정 |
|---|---|---|---|
| 1. 콘솔 안 로그인 화면 + 서명 쿠키 | 로그인 → 로그아웃 → 재로그인이 실제처럼 동작 | 배포 후 점검(`console_gate.py`)·ADR-007 수정 | **채택** |
| 2. Entra Easy Auth 복원 | 진짜 Microsoft 로그인 화면 | 테넌트 관리자 동의 없이는 막힘 | 기각 |
| 3. 화면만 있는 로그인(버튼이 `/`로 이동) | 서버 변경 거의 없음 | 주소 직접 입력·뒤로 가기로 우회, 로그아웃이 흉내뿐 | 기각 |

## 설계
- **켜는 조건:** `ConsoleDeps.demo_login: bool`(기본 `False`). `build_deps`가 환경 변수 `CONSOLE_DEMO_LOGIN=true`일 때 켠다. Bicep은 데모 모드(`consoleAuthEnabled=false`)에서 `CONSOLE_AUTH_MODE=demo`와 함께 이 변수를 넣는다(`infra/resources.bicep`). 데모 주체가 없으면(Easy Auth 모드) 이 설정은 무시한다.
- **로그인 화면 `GET /login`:** 사이드바 없는 단독 페이지. 기존 콘솔 브랜드(로고·"AMA Lending 심사 콘솔")와 스타일(`console.css`)을 따르고 언어 전환(`_lang.html`)을 둔다. ID·비밀번호 칸에 데모 값이 미리 채워져 있다.

  ```
  ┌───────────────────────────────┐
  │   [A] AMA Lending 심사 콘솔     │
  │                               │
  │   아이디   [ demo.officer    ] │
  │   비밀번호 [ ••••••••        ] │
  │                               │
  │   [          로그인          ] │
  │   데모 계정이 미리 입력돼 있습니다 │
  └───────────────────────────────┘
  ```
- **로그인 처리 `POST /login`:** 아이디가 데모 아이디(`demo.officer`)이고 비밀번호가 비어 있지 않으면 성공한다. 저장된 비밀번호는 없다(비밀 값 커밋 방지). 실패하면 422와 함께 같은 화면에 오류 문구를 보인다. 성공하면 세션 쿠키를 주고 `next`로 303 리디렉션한다. `next`는 `/`로 시작하고 `//`로 시작하지 않는 상대 경로만 받고, 아니면 `/`다.
- **세션 쿠키:** 이름 `ama_demo_session`, 값은 `발급 시각.HMAC` 서명(키는 `csrf_key`처럼 가명처리 키에서 `b"console-demo-login"`으로 파생). 유효 8시간. `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`. 레플리카가 바뀌어도 같은 키라 유지된다.
- **관문:** `viewer()`(따라서 `decider()`와 모든 심사역 화면·HTMX 조각·`/i18n/translate`)가 `demo_login`이 켜져 있으면 유효한 쿠키를 요구한다. 없을 때:
  - HTMX 요청(`HX-Request` 헤더): 401 + `HX-Redirect: /login`
  - 그 밖의 GET: 303 → `/login?next=<원래 경로와 쿼리>`
  - 그 밖(POST 등): 401
- **열려 있는 경로:** `/login`, `/logout`, `/healthz`, `/static/*`, 고객 화면(`customer()` 경유: `/borrower…`, `/apply`). 고객 콘솔은 이번 범위가 아니다.
- **로그아웃 `GET /logout`:** 쿠키를 지우고 `/login`으로 303. `base.html`의 사용자 영역은 Easy Auth 모드면 기존 `/.auth/logout`, 데모 로그인이 켜져 있으면 `/logout` 링크를 보인다. 데모 로그인이 꺼진 데모 모드는 지금처럼 링크가 없다.
- **영문 화면:** 로그인 화면 문구를 `src/console/locales/en/base.json`에 더한다.
- **배포 후 점검:** `src/ops/console_gate.py`의 데모 모드 확인은 `/`가 같은 호스트의 `/login`으로 303 리디렉션하고 `/login`이 200인지 본다. 그 밖의 리디렉션은 지금처럼 "Easy Auth가 아직 켜져 있음" 오류다.
- **문서:** ADR-007의 결정·결과에 "데모 로그인 화면은 장면용이며 인증이 아니다, 결정 기록은 `demo-operator`"를 더하고, `docs/architecture.md` 콘솔 행의 인증 칸을 맞춘다.

## 빌더에게 맡기는 것
- 로그인 화면의 세부 배치·문구 다듬기(기존 콘솔 스타일 안에서).
- 테스트 배치: 기존 `tests/console/test_app.py`·`tests/ops/`의 관련 파일에 관문·로그인·로그아웃·`next` 검증·점검 변경 케이스를 더한다.

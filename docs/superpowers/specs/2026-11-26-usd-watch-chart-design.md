# USD 감시 일지 두 단 그래프 설계

작성일: 2026-11-26 · 대상: USD 대출 화면(`/loans/<id>`) · 선행 설계: `2026-11-26-usd-postloan-agent-watch-design.md`(PR #11)

## 1. 의도와 이유

PR #11로 USD 사후 화면에 "에이전트 감시 일지"가 생겼습니다. 하지만 한 주의 판단을 이해하려면 아래 네 카드를 오르내려야 합니다.

- 감시 일지(최신 주가 위)
- 주간 흐름과 탐지기(1주차가 위). USD 행에는 `buffer_days`가 없어서 버퍼 선이 그려지지 않습니다. 매출 막대, 기준선, ▲만 나옵니다.
- 주간 정산(PG 원장) 표
- 주간 마켓 스냅샷 표

게다가 정산 표와 마켓 표에는 어느 칸이 신호를 냈는지 표시가 없습니다. 일지 칩에는 `W:5:orders_vs_expected = 0.514` 같은 내부 ID가 그대로 노출됩니다.

사용자는 **그래프로 시각화해서 보여 주는 것이 중요하다**고 했습니다. 목업 세 안 가운데 **3번 "두 단 결합"**을 골랐습니다.

- 위 단은 "누가 먼저 움직였나"(선행·후행 신호)를 보여 줍니다.
- 아래 단은 "그래서 갚을 수 있나"(현금 여력)를 보여 줍니다.
- 두 단은 에이전트 단계 띠와 주차 축을 함께 씁니다.

이렇게 하면 왜 경보가 울렸는지와 상환이 위험한지가 한 세로줄에 맞춰집니다.

대표 사례는 dailylook `app-20261126-373b6b`입니다.

| 주차 | 일어난 일 | 단계 |
|---|---|---|
| 4 | 정산 주문이 먼저 하락 | 관찰 |
| 5 | 마켓 등급 Gold → Silver | 중간 |
| 6 | 은행 매출이 75% 아래로 하락 | 중간 유지 |
| 7 | 예상 최저 잔액이 음수 | 높음 |
| 13 | 3회차 미납 | — |

그래프에서 이 순서가 한눈에 보여야 합니다.

## 2. 목표 · 비목표 · 반목표

**목표**
- 감시 일지 카드 맨 위에 두 단 그래프를 둡니다. 재생이 진행되면 한 주씩 채워집니다.
- 그래프의 주차 칸을 누르면 그 주의 일지 항목(`#journal-w{n}`)으로 이동합니다.
- 일지 증거 칩을 사람이 읽는 표기로 바꿉니다. 예: `정산 주문 기대 대비 51.4%`, `예상 최저 잔액 -$254`, `마켓 등급 Silver`.
- 정산 표, 마켓 표, 주간 흐름 표는 일지 카드 아래의 접힌 "원장 전체 보기"로 옮깁니다. 신호를 낸 칸은 색으로 강조합니다.

**비목표**
- KRW 화면과 경로(`/legacy`)는 바꾸지 않습니다.
- 일지 필드가 없는 옛 USD 재생 화면은 지금 그대로 둡니다.
- 아래쪽 "기대 입금 대비 실제", "4주 잔고 전망", 경보·미납 카드는 바꾸지 않습니다.
- 에이전트, 탐지기, 저장 데이터는 바꾸지 않습니다. 화면만 다시 짭니다.

**반목표** (그대로 작동해도 실패로 봅니다)
- 처음부터 13주 값을 한꺼번에 보여 주는 히트맵이나 타임라인. 선행 설계 §4.3에서 기각했습니다.
  - 그래프는 재생된 주차까지만 값을 그리고, 이후 칸은 빈 점선 칸으로 둡니다.
- 새 클라이언트 스크립트나 차트 라이브러리. 갱신은 지금처럼 meta refresh로만 합니다.
- 비교 트랙 문구("bank only", "N weeks earlier")의 재등장. 선행 설계 52행입니다.
- 화면의 중심이 데이터 그림으로 옮겨 가는 것.
  - 그래프는 일지 카드 안에 넣고 단계 띠를 맨 위에 둡니다. 중심은 계속 에이전트의 알람 판단입니다.

## 3. 제약

- 서버에서 SVG를 그립니다. `src\console\charts.py`의 도구(`columns`, `line`, `signed_line` 계열)와 `_charts.html` 매크로 방식을 따릅니다.
  - 툴팁은 SVG `<title>`을 씁니다.
  - 주차 링크는 SVG `<a href="#journal-w{n}">`를 씁니다.
- 화면 문구는 기존 관례대로 한국어 원문 `_()`에 영어 번역을 붙입니다(`src\console\locales\en\monitoring.json`). USD 화면은 영어로 보입니다.
- 새 화면은 `usd and v.journal`일 때만 그립니다. 그 밖의 경우는 지금 템플릿 경로를 그대로 탑니다.
- 툴팁과 칩의 금액 표기는 USD 표시 규칙(`usd_cents`, `display_usd`)을 따릅니다.

## 4. 접근 방식

| 안 | 내용 | 판단 |
|---|---|---|
| **서버 SVG (채택)** | 기존 `charts.py` 도구를 조합해 두 단 SVG를 만듭니다. | meta refresh와 잘 맞고, 툴팁과 링크를 쓸 수 있고, 새 의존성이 없습니다. |
| 브라우저 차트 (Chart.js 등) | 클라이언트에서 그립니다. | 새 스크립트가 필요하고, 새로 고침 때마다 화면이 깜빡입니다. 반목표에 걸려 탈락했습니다. |
| 이미지 (matplotlib PNG) | 서버에서 그림 파일을 만듭니다. | 툴팁과 링크가 없고 라이브러리가 하나 늘어서 탈락했습니다. |

그래프 형태는 목업 세 안을 비교해 사용자가 3번 "두 단 결합"을 골랐습니다.
- 1번 선행·후행만: 부족액이 보이지 않습니다.
- 2번 현금 여력만: 어느 자료가 먼저 움직였는지 흐려집니다.

## 5. 사용자가 정한 것

```
[KPI 4칸] [사실]
┌ 에이전트 감시 일지 ─────────────── 열린 사건: 높음 · 4주차부터 ┐
│ 단계 띠   정상 정상 정상 관찰 중간🔔 중간 높음🔔 ┆ ┆ ┆ ┆ ┆ ┆      │
```

### 5.2 두 단 그래프 내용

**x축**
- 1~13주 고정 13칸입니다(`REPLAY_WEEKS`).
- 처리된 주차까지만 값을 그립니다. 나머지 칸은 단계 띠 자리에 점선 빈칸만 둡니다.
- 가장 최근 처리 주는 축 글자를 굵게 하고, 세로로 옅게 강조합니다.

**단계 띠** (맨 위)
- 일지 줄의 `stage`를 색으로 칠합니다: 정상, 관찰, 중간, 높음, 해소.
- 그 주에 `alert_id`가 있으면 🔔와 단계명을 띠 위에 표시합니다.
- 띠 칸은 `<title>`로 "N주차 · 단계"를 보여 줍니다.

**위 단: 기대 대비 비율 선**
- 정산 주문은 선 두 개로 그립니다. (사용자 결정)
  - 굵은 실선: 행의 `orders_vs_expected`(최근 3주 합 기준). `sales_slump` 경보의 근거 숫자와 같습니다.
  - 옅은 점선: 그 주 한 주 값 `order_gross_cents / expected_orders_cents`. `orders_dip`(관찰)의 근거입니다. 4주차 27% 급락이 여기서 보입니다.
- 은행 매출은 행의 `revenue_vs_expected`(최근 3주 합 기준) 실선 하나만 그립니다. 은행에는 한 주 단위 신호가 없기 때문입니다. (제 판단)
- y축은 0~120%로 하고, 값이 그보다 크면 위쪽에서 자릅니다.
- 탐지 기준 75% 점선을 긋습니다. `usd_monitoring.py`의 `sales_slump`, `inflow_drop` `.75`와 `ORDERS_DIP_RATIO = 0.75`가 모두 같은 값입니다.
- 값이 없는 주(`None`)에서는 선을 끊습니다.
- 점마다 `<title>`로 "N주차 정산 주문 51.4%"를 보여 줍니다.

**위 단 아래: 마켓 칩 줄**
- 주차마다 `mkt_grade`를 칩으로 보여 줍니다.
- 그 주 일지의 market 출처에 신호가 있으면 칩 테두리를 강조합니다.
- 마켓 행이 없는 주는 "–"로 둡니다.

**아래 단: 현금 여력**
- 막대 두 개를 나란히 둡니다.
  - 빈 막대: PG 주문액 `order_gross_cents`
  - 채운 막대: 은행 입금 `revenue_cents`
  - 두 막대를 나란히 두면 정산 시차가 보입니다.
- 선은 예상 최저 잔액 `projected_min_balance_cents`입니다. 음수까지 그리고, $0 기준선을 둡니다.
- 음수 점은 빨간색으로 그리고, `<title>`에 부족 예상일 `shortfall_date`를 넣습니다.
- 상환일은 `loan.repayment` 회차의 `due_on`이 속한 주차 칸 아래에 💵와 날짜로 표시합니다.
  - 상환 일정은 대출 시점에 이미 정해진 약정입니다. 그래서 아직 재생되지 않은 주에도 회색으로 보여 줍니다.
  - 관측값이 아니므로 "처리 전 주는 비워 둔다"는 반목표에는 걸리지 않는다고 판단했습니다. (제 판단)
- 처리된 주의 납부 회차는 기본색, 미납 회차는 빨간색으로 표시합니다.

**주차 링크**
- 각 주차 칸 전체(띠부터 축까지 세로줄)를 `<a href="#journal-w{n}">`로 감쌉니다.
- 처리되지 않은 주는 링크가 없습니다.

### 5.3 일지 증거 칩의 사람 표기

- 칩 형태는 `[출처 색] 라벨 값`입니다. 내부 ID(`W:5:…`)는 칩 글자에서 빼고 `<title>`에만 남깁니다.
- 라벨 표는 지표 이름 접미사로 찾습니다.

| 지표 | 라벨 | 표기 |
|---|---|---|
| `orders_vs_expected` | 정산 주문 기대 대비 | % |
| `revenue_vs_expected` | 은행 매출 기대 대비 | % |
| `projected_min_balance_cents` | 예상 최저 잔액 | $ |
| `due_balance_cents` | 상환일 잔액 | $ |
| `order_gross_cents` | 주문액 | $ |
| `expected_orders_cents` | 기대 주문액 | $ |
| `held_cents` | 보류액 | $ |
| `mkt_grade` | 마켓 등급 | 그대로 |
| `mkt_cancel_rate` | 취소율 | % |
| `return_rate` | 반품률 | % |
| `deduction_rate` | 공제율 | % |
| `mkt_rating` | 평점 | 소수 2자리 |
| `mkt_penalties` | 계정 경고 | 건 |
| `recon_ratio` | 정산 대사율 | % |
| `orders_vs_prior_year` | 전년 대비 주문 | % |

- 이 표는 USD 신호가 인용하는 지표 전부입니다. `usd_monitoring.py`의 `_EVIDENCE`와 `BASIS_METRICS`에서 가져왔습니다.
- 표에 없는 지표가 나중에 생기면 ID와 값을 그대로 보여 줍니다. 깨지지 않게 하기 위한 안전장치일 뿐이고, 정상 경로에서는 나오지 않아야 합니다. (제 판단)
- 사람 표기는 **일지 카드에만** 적용합니다. 경보 카드의 증거 칩은 비목표(경보 카드 불변)에 따라 지금처럼 둡니다. (제 판단)

### 5.4 원장 전체 보기 (접힘)

- 하나의 `<details>`(기본 닫힘) 안에 기존 표 세 개를 지금 열 구성 그대로 둡니다.
  - 주간 흐름과 탐지기
  - PG 정산
  - 마켓
- 그 주 일지 신호의 `metric_ids`가 가리키는 열의 칸에는 `warn` 강조를 붙입니다. 예: 5주차 `orders_vs_expected` → PG 표에 같은 열이 없으면 그 주 주문액 칸.
- 강조할 칸이 없는 신호는 무시합니다.

## 6. 빌더에게 맡기는 것

- 색상 값, 크기, 여백, 범례 배치. 기존 `_charts.html`의 색 이름 체계를 따르면 됩니다.
- 두 단 그래프를 `charts.py`에 새 함수로 둘지, 기존 함수 조합으로 만들지.
- 아래 단 $ 축의 범위를 고정할지 자동으로 잡을지. 새로 고침 때 축이 출렁이는 정도가 과하지 않으면 됩니다.
- 신호 지표와 원장 표 열의 정확한 대응표.

# 이정운 저자 사례로 보완하는 AMALend 백서

금융권 아키텍트와 리스크·엔지니어링 책임자가 다음 설계 검토에서 결정권자, 근거가 없을 때 멈출 지점, 장애 뒤 복원 가능한 범위를 먼저 확인하도록 돕는다.

## 접근 방식

기존 백서의 일곱 원칙과 체크리스트를 유지하고 서론·원칙별 본문·결론의 아홉 작성 안내를 짧은 저자 사례로 교체한다(사용자 선택). 세 사건 중심의 회고로 다시 쓰는 안도 검토했지만 기존 원칙별 근거를 찾아보기가 어려워진다.

## 편집 기준

- 저자는 ‘이정운’. 직책·고객 일화·직접 인용·발행 여부를 추정하지 않는다. 사례는 대화에서 확인한 저자의 요구와 저장소에 기록된 팀의 행동을 구분해 쓴다.
- 각 사례에서 어떤 판단이 필요했고 구현이나 운영에서 무엇을 확인했는지 설명하고 근거를 연결한다. 서론과 결론은 같은 수치를 반복하지 않고 독자의 설계 질문으로 이어 준다.
- 현재 구성과 과거 벤치마크의 시점·모델·표본을 구분한다. 합성 신청의 검토 통과는 실제 신용 성능이 아니며, 반복 배포는 데이터 재해 복구가 아니다.
- 반영 범위는 `docs/thought-leadership.md`의 저자 표기, 사례, 이에 딸린 요약·출처·발행 전 점검 문구다. 원 보고서나 운영 시스템은 수정하지 않는다.
